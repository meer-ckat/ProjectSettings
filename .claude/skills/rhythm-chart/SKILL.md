# 리듬게임 채보 스킬

이 프로젝트 채보를 만들고 고치는 방법. 스크립트는 `.claude/skills/rhythm-chart/scripts/`에 있고, `python -I`로 프로젝트 루트에서 실행한다.

## 게임이 채보를 읽는 방식 (먼저 알아 둘 것)

- 파일: `Assets/Resources/<id>.json`. 게임은 `Resources.Load(id)`로 읽는다(확장자 없이).
- 형식: `{ "bpm": 122.0, "gridOffset": 0.35, "noteList": [ {"interval": 1.0, "input": 1, "message": ""} ] }`
  - `interval` = 앞 노트와 간격(박). **0이면 동시치기**. 게임은 음악 0초부터 누적한다.
  - `input` 0/1/2 = 레인 A/B/C = 키보드 **A/S/D**. `input` 3 = 4번째 칸(F키). 펌프 발판 채보(`<곡>_pump_*`)에서만 쓴다. 메인 메뉴 SETTINGS에서 입력을 펌프로 바꾸면 이 채보를 4레인으로 친다. 키보드 모드는 혹시 3이 섞여 있어도 불러올 때 뺀다.
  - `gridOffset` = 첫 마디가 시작하는 초. 노트 에디터 그리드용이고 게임은 안 쓴다. 박자 세기를 따질 때는 이 값 기준으로 마디를 센다.
  - `message` = 그 노트 박이 지나갈 때 `DialogueManager.Send`로 보낸다. 노트 에디터로 저장한 파일은 모든 노트에 `"message": ""`가 있다.
- 난이도 연결: Menu 씬 `SongSelect`의 곡 항목 `easy_id`/`normal_id`/`hard_id`. 비어 있으면 `id` 채보를 쓴다. 쉬움·매우 쉬움은 둘 다 `easy_id`.
  Menu 씬 파일을 직접 고칠 때는 **Unity에서 Menu 씬이 안 열려 있는지 먼저 확인**한다(열려 있으면 사용자에게 인스펙터에서 넣어 달라고 한다).
- 음원: `SongSelect.SelectedSong`(곡 id)으로 따로 읽는다. 난이도별 채보 id가 달라도 음원은 같다.

## 판정과 손가락 (난이도를 가르는 진짜 이유)

- 판정 범위(Game 씬 기본, 중간 난이도): Perfect ±0.05s, Great ±0.1s, Good ±0.15s. 곡 선택 난이도 배율(어려움 0.7 ~ 매우 쉬움 2)을 곱한다. **Good이나 Miss가 나오면 콤보가 끊긴다.** Good 범위보다 0.1초 더 일찍 누르면 그 노트가 Miss(얼리 미스, 연타 방지). 그보다 이른 헛친 입력은 콤보를 안 끊는다.
- 같은 레인 노트 사이가 **0.2초보다 짧으면 위험**하다. 한 노트를 0.1초 넘게 늦게 치면 판정이 다음 노트를 가져가서, 앞 노트가 Miss가 되고 한 칸씩 밀린다.
- A는 약한 손가락(약지나 새끼)이다. 빠른 구간·연타가 A에 몰리면 체감 난도가 확 오른다. 동시치기를 하나로 줄일 때도 A보다 S/D를 남긴다.

## 작업 흐름

### 1. 검토 — 항상 여기서 시작하고 끝낸다
```
python -I .claude/skills/rhythm-chart/scripts/chart_tool.py stats Assets/Resources/<id>.json [--compare 다른.json]
```
보고 말할 것: 노트 수·길이·평균 초당 노트, 2초 창 최대(`max_in_2s`), 레인 비율, 동시치기 수, 0.2초 미만 같은 레인 연타 수와 위치(초), 그리드 밖 노트, 메시지 목록.
풀콤을 막는 지점은 **초 단위 위치**로 짚는다(사용자는 노트 에디터 시계로 찾는다).

### 2. 쉬운 난이도 파생 (사람이 찍은 채보가 있을 때 — 가장 품질이 좋다)
```
python -I .claude/skills/rhythm-chart/scripts/chart_tool.py thin <원본>.json <원본>_easy.json --profile easy   # 또는 normal
```
박자 칸 밖 노트 제거 → 동시치기 정리 → 최소 간격(센 박 우선) → 2초 밀도 상한 → 같은 레인 연타는 리듬을 두고 레인만 이동 → 지워진 노트의 메시지는 그 이전 노트로 옮김.
프로필 기준은 `chart_tool.py`의 `PROFILES`에 있다. 쉬움 목표: 평균 초당 1.5~2개, 동시치기 0, 같은 레인 간격 1박 이상.
보통: 동시치기는 정박에만, 마디당 1개, 세 키 없음. 
**어려움 다듬기**는 `--profile hard`: 리듬(셋잇단 포함)은 두고 32분 같은 초고속, 빠른 줄기 속·뒷박 동시치기(A+D 연타가 되는 것), 마디 첫 박이 아닌 세 키 동시치기, 0.2초 미만 같은 레인 연타만 고친다. 결과는 `<원본>_hard.json`으로 따로 만들어 `hard_id`에 연결한다.
동시치기를 하나로 줄일 때는 앞뒤 노트와 안 겹치는 레인을 고른다(원래 동시치기에 없던 레인이어도 됨). 그래야 줄인 자리가 새 연타가 되지 않는다.
**원본 파일은 덮어쓰지 않는다.** 새 파일을 만들고 stats로 원본과 비교해 보여준 뒤, 난이도 칸에 연결한다.

### 3. 새 곡 초안 (사람 채보가 없을 때)
1. Unity에서 음원을 wav로 뺀다: `scripts/export_wav.cs.txt` 내용을 Unity MCP `execute_code`로 실행(CLIP 경로만 바꿈). **플레이 중이면 하지 말 것**.
2. BPM·오프셋: 노트 에디터의 "자동" 버튼 값이나 사용자에게 받는다. 추측한 값으로 진행하지 않는다.
3. 구간 나누기: `audio_tool.py sections Temp/chart/<곡>.wav --bpm B --offset O` → 조용/중간/큼 구간(인트로·벌스·코러스·브리지 추정).
4. 초안: `audio_tool.py draft Temp/chart/<곡>.wav Assets/Resources/<id>_hard.json --bpm B --offset O` → 소리가 튀는 지점을 16분 그리드에 붙인 '어려움 원본'. 레인은 소리 높이(낮음 A, 중간 S, 높음 D).
5. `thin`으로 쉬움/보통을 파생하고, 1번 검토를 돌린다.
6. MIDI가 있으면 Unity 메뉴 `Tools/MIDI to Stage`가 더 정확하다. 보컬 트랙만 쓰면 보컬 리듬 구간이 깔끔하다.

초안은 귀로 확인한 게 아니다. 결과를 넘길 때 **"노트 에디터에서 들으면서 다듬어야 하는 초안"**이라고 분명히 말한다.

### 3-1. 펌프(발판) 채보 만들기
펌프 모드 = 펌프 잇 업 발판(USB, 4칸 = 키 A S D F). 손 채보를 그대로 밟게 하지 않고 **발판 전용 채보**를 따로 둔다.
```
python -I .claude/skills/rhythm-chart/scripts/chart_tool.py foot Assets/Resources/<어려움>.json Assets/Resources/<곡id>_pump_easy.json --profile pump_easy
# pump_normal, pump_hard도 같은 원본(어려움)에서
```
- 파일 이름은 꼭 `<곡id>_pump_easy|normal|hard`. 곡 선택이 펌프 모드일 때 이 이름을 찾고, 없으면 키보드 채보(3레인)를 쓴다. 매우 쉬움은 easy.
- 리듬: 쉬움 4분음표(2초 2개), 보통 4분음표(2초 4개), 어려움 8분까지(2초 5개). 점프(양발 동시)는 쉬움 없음, 보통 = 마디 첫 박에 앞뒤 2박이 빌 때만, 어려움 = 마디 첫 박만. (실제 발판으로 밟아 보고 한 단계씩 낮춘 기준. 어려움 ≈ 예전 보통)
- 레인: 1박 또는 0.8초(`alt_s`)보다 붙은 스텝은 왼발(A S)·오른발(D F)을 번갈아, 느리면 원래 손 레인 방향을 따른다. 점프 바로 뒤 같은 칸은 같은 발 옆 칸으로 옮긴다. 점프는 마디 첫 박이면 A+F, 아니면 S+D.
- 노트 절반 이상이 8분 격자 밖인 채보(셔플·MIDI 그대로)는 격자 거르기를 끄고 간격으로만 고른다.
- 손 채보(키보드)에는 `input` 3을 넣지 않는다. 기록은 키보드와 따로(`best_<곡>_pump_<난이도>`, `score_<곡>_pump`).

### 4. 메시지(배너) 넣기
- 배너 목록은 `Assets/Scripts/RhythmCallout.cs`의 `callouts`: `vocal` "이제 보컬 리듬!", `drum` "다시 드럼 리듬!", `chorus` "코러스! 몰아친다", `climax` "클라이맥스!", `finale` "마지막까지!". 새 이름을 쓰면 목록에도 추가해야 뜬다.
- 리듬이 바뀌는 지점보다 **약 1마디(2초) 앞 노트**에 단다. 배너가 1.2초 떠 있어서 읽고 나면 바뀐다.
- 리듬 성격 판단: 정박 비율이 높으면 드럼(킥) 리듬, 엇박·셋잇단·16분이 많으면 보컬 리듬. 음량이 크게 뛰는 마디 = 코러스, 곡 후반 최대 = 클라이맥스.
- 파일에 넣을 때는 해당 노트의 `"message": ""` 줄만 바꾸고(서식 유지), 바꾼 뒤 노트 수·interval·input이 그대로인지 확인한다. 노트 위치는 번호와 초를 둘 다 대조한다.

## 넘기기 전 확인

- stats를 다시 돌려 숫자로 보고한다(원본과 비교).
- 메뉴 난이도 칸에 연결했는지, 안 했다면 사용자가 할 일을 말한다.
- Unity가 플레이 중이면 컴파일·씬 수정을 미루고, 멈춘 뒤 다시 들어가야 반영된다고 알린다.
