카톡식 스토리 대사창

지금 대사창 모양(흰 상자·검은 테두리·초상화·이름·타자 효과)은 그대로 둔다. 바뀌는 건 두 가지뿐. 대사가 나올 때마다 상자가 새로 생기고 앞 상자는 위로 밀려 올라간다. 그리고 인물에 따라 상자가 왼쪽이나 오른쪽에 붙는다.

ESC 건너뛰기
클릭·스페이스 = 글 다 보이기 → 다음 대사

규칙

  • JSON형식 그대로. speaker, portrait, text 세 개. 새 필드 없음.
  • 왼쪽·오른쪽처음 나온 인물 = 왼쪽, 두 번째로 나온 인물 = 오른쪽, 세 번째 = 다시 왼쪽… 한 번 정해진 자리는 끝까지 안 바뀐다.
  • 초상화왼쪽 상자는 초상화가 왼쪽 끝, 오른쪽 상자는 초상화가 오른쪽 끝(바깥쪽). 이름·글도 그쪽으로 정렬.
  • 나레이션"나레이션"이거나 speaker가 비면 가운데 상자, 초상화 없음.
  • 위로 밀기새 상자는 지금처럼 아래에서 튀어 올라오고, 떠 있던 상자는 전부 상자 높이+간격만큼 위로. 지난 상자는 살짝 흐리게(0.6), ▼는 맨 아래 상자에만.
  • 조작지금과 같음. 누르면 글 다 보이기 → 다음 대사. ESC = 전부 건너뛰기. 끝나면 지금처럼 아래로 빠지고 음악 시작.

구현 순서

  1. 상자 하나 만드는 함수로 떼기. 지금 Build()에 있는 상자·초상화·이름·글·▼ 만드는 부분을 MakeBox(Line, side)로 옮긴다. 스타일·폰트·텍스처는 한 번만 만들고 같이 쓴다. 상자 폭은 화면의 76%, 높이 230, 간격 16(1080p 기준, 지금 300에서 줄임). 화면에 상자 4개가 꽉 차게 보인다.
    StoryDialogue.cs · Build() 나누기
  2. 왼쪽·오른쪽 정하기. Dictionary<string, int>에 인물이 처음 나온 순서를 적고, 짝수면 왼쪽 홀수면 오른쪽. 오른쪽이면 초상화 x를 상자 오른쪽 끝으로, 글 정렬을 UpperRight로.
    StoryDialogue.cs · Next()
  3. 위로 밀기. 상자마다 그 상자에 딸린 항목 묶음(GUIItem[])과 목표 y를 들고 있는다. 새 대사가 오면 전부 목표 y에서 (높이+간격)을 빼고 MoveTo 0.25초.
    StoryDialogue.cs · 새 리스트 boxes
  4. 화면 위로 나간 상자 지우기. 목표 y가 0보다 위로 가면 GUIManager.Unregister.
  5. 끝내기. Finish()는 지금 Wave를 남은 상자 전부에 건다. EndedDsp 기록은 그대로.
  6. placeholder 스토리 6곡. 위 미리보기 대사를 Resources/Story/의 각 곡 파일에 넣는다. 첫 줄 나레이션에 임시 스토리를 넣어 나중에 찾기 쉽게. _example.json 설명도 새 규칙으로.

JSON 예시

{
  "lines": [
    { "speaker": "나레이션", "portrait": "", "text": "임시 스토리. 연습실, 저녁 7시." },
    { "speaker": "민지", "portrait": "Portraits/minji", "text": "오늘도 Bounce 첫 박 놓치면 치킨이다." },
    { "speaker": "주인공", "portrait": "Portraits/hero", "text": "이번엔 안 놓쳐. 밤새 손목 풀었거든." },
    { "speaker": "민지", "portrait": "Portraits/minji", "text": "말만. 시작한다?" }
  ]
}

민지가 먼저 나왔으니 왼쪽, 주인공은 오른쪽.

조심할 것

  • 그룹은 자식을 안 끌고 다닌다. 상자만 옮기면 초상화·글이 제자리에 남는다. 지금 parts처럼 상자마다 묶음을 만들어 같이 옮긴다.
  • 연타하면 위치가 어긋날 수 있다. MoveTo는 "지금 위치"에서 출발한다. 그래서 목표 y를 따로 들고 거기서 빼야 상자가 겹치지 않는다.
  • 상자 높이를 줄이면 긴 대사는 잘린다. 230 높이에 38px 글씨면 세 줄쯤. 긴 대사는 두 줄로 나눠 쓴다.

뺀 것: 자리를 JSON에서 직접 정하는 side 필드. 자동 배정이 안 맞는 장면이 생기면 그때 붙인다.
